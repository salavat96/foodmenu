# План разработки Telegram-бота с меню и рецептами (2 недели)

## Цель

Telegram-бот, который:

1. По запросу показывает рецепт **пошагово**.
2. Составляет **меню на период** (неделя / две недели / произвольный срок) с учётом
   финансового запроса (бюджета), аллергий и нелюбимых продуктов; распределяет блюда
   по завтраку/обеду/ужину и **напоминает о меню** во время, которое настраивает сам пользователь.
3. Отсекает **нетематические запросы** (защита от флуда и не относящихся к теме сообщений).
4. Строит **меню для похудения** по разным типам диет исходя из цели и образа жизни пользователя.

## Стек

- Python 3.11, **aiogram 3** (FSM, роутеры, middlewares) — де-факто стандарт для TG-ботов на Python.
- **SQLAlchemy 2.0 (async)** + SQLite для локальной разработки, с возможностью переключения на PostgreSQL
  через `DATABASE_URL` (для продакшена).
- **APScheduler** — ежедневные и ежеминутные задачи для напоминаний.
- Docker/docker-compose — для деплоя.
- pytest — юнит-тесты сервисов (генерация меню, антиспам-фильтр).

## Модель данных (кратко)

- `User` — telegram_id, аллергии, нелюбимые продукты, тип диеты, дневной бюджет, часовой пояс.
- `Recipe` / `Ingredient` / `RecipeStep` — рецепт, ингредиенты, шаги приготовления.
- `MenuPlan` / `MenuEntry` — сгенерированное меню на период и распределение блюд по дням/приёмам пищи.
- `ReminderSetting` — время напоминания на каждый приём пищи, настраиваемое пользователем.

## Разбивка по дням

### Этап 0 — Архитектура и окружение (День 1)
- Выбор стека, структура репозитория, конфиг через `.env`, Docker/docker-compose.
- Схема БД, базовые модели SQLAlchemy.
- **Критерий готовности:** бот стартует, отвечает на `/start`.

### Этап 1 — Рецепты пошагово, ядро бота (Дни 1–4)
- Модели `Recipe`, `Ingredient`, `RecipeStep`.
- Сид-данные: набор рецептов на завтрак/обед/ужин.
- Категории рецептов, поиск по названию/ингредиенту.
- Пошаговый показ рецепта: список ингредиентов → шаги с навигацией «Далее/Назад».
- **Критерий готовности:** пользователь выбирает рецепт и листает шаги приготовления.

### Этап 2 — Защита от нетематических запросов (Дни 4–5, встроено с первого дня)
- Middleware-фильтр: разрешённые темы (рецепты/еда/меню/настройки) пропускаются,
  остальное — вежливый ответ-заглушка + подсказка, что умеет бот.
- Rate limiting на пользователя (защита от флуда).
- **Критерий готовности:** случайные/несвязанные сообщения не ломают сценарии и не создают шум.

### Этап 3 — Меню на период с учётом бюджета и ограничений (Дни 5–9)
- FSM-анкета: период (7/14/произвольно дней), бюджет (низкий/средний/высокий), аллергии,
  нелюбимые продукты (если не заданы в настройках — спросить и сохранить в профиль).
- Алгоритм подбора рецептов под ограничения (исключение аллергенов и нелюбимых продуктов,
  фильтр по бюджету, ротация блюд без повторов подряд).
- Формирование расписания завтрак/обед/ужин на каждый день периода, красивый вывод.
- Сохранение `MenuPlan`/`MenuEntry` в БД.
- **Критерий готовности:** пользователь получает готовое меню на 7/14 дней с учётом ограничений.

### Этап 4 — Напоминания (Дни 8–9, параллельно с Этапом 3)
- `ReminderSetting`: время напоминания отдельно для завтрака/обеда/ужина.
- Экран настройки времени в профиле.
- Планировщик (APScheduler), задача раз в минуту проверяет, кому пора напомнить,
  и присылает сегодняшнее блюдо по расписанию.
- **Критерий готовности:** в заданное пользователем время приходит напоминание с блюдом на сегодня.

### Этап 5 — Меню для похудения / по типу диеты (Дни 9–12)
- Типы диет: обычная, низкоуглеводная, кето, вегетарианская, веганская, высокобелковая,
  средиземноморская (расширяемый список).
- Цель: снижение веса / поддержание / набор массы — влияет на калорийность и подбор рецептов.
- Переиспользование движка генерации меню (Этап 3) с доп. фильтром по тегам диеты и калорийности.
- **Критерий готовности:** пользователь выбирает диету и цель — получает меню под это.

### Этап 6 — Настройки профиля (Дни 11–12)
- Единый экран: аллергии, нелюбимые продукты, диета, бюджет по умолчанию, время напоминаний, часовой пояс.

### Этап 7 — Тестирование и полировка (Дни 12–14)
- Юнит-тесты сервисов (антиспам-фильтр, генератор меню).
- Ручное тестирование всех сценариев, обработка ошибок и edge-cases (нет подходящих рецептов и т.д.).
- Финальные тексты, деплой в Docker, README с инструкцией запуска.

## Текущий статус

Реализовано в этом коммите (первая итерация): каркас проекта, БД-модели под все 4 блока,
рабочий сценарий «Рецепты пошагово», антиспам-миддлварь, базовый генератор меню
(используется и для обычного меню, и для меню похудения через параметр диеты),
настройка напоминаний и планировщик отправки. Дальше — наполнение базы рецептов,
доработка UX и тестирование по плану выше.
